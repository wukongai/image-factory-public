# 安装后，怎么真正生成图片？

图片工厂负责海报模板、提示词、参考图和小店交接；真正生成图片需要一个可用的生图后端。你可以用 Agent 已有能力，也可以接自己的 API。作者不提供私人 Key 或免费额度。

## 路线一：让 Agent 用内置生图工具（优先）

安装后直接对 Agent 说：

> 使用 image-factory 制作商品海报。先确认你是否有能实际生成并保存图片的工具；如果有，读取任务提示词、加载授权参考图并生成 PNG，然后验收、展示，交回小店 HTML 清单。如果没有，带我走 API 接入，不要只交提示词，也不要让我把 Key 发在聊天里。

Agent 执行：定位本 Skill → 编译任务 → 读取 manifest 的 `render_handoff.prompt_file` → 按 `assets` 加载参考图 → 调用真实图片工具并保存文件 → 用 `accept_image.py` 验收。不能只凭 Agent 名称判断它有生图能力，必须以当前会话实际可调用的工具为准。已有 MCP 生图工具同样走这条路径，其凭证由该工具管理。

## 路线二：使用自己的 API Key

公开版自带 `scripts/image_backend.py`。支持 OpenAI Images API：无参考图走 generations，有参考图走 edits。接入协议见 [官方图片生成文档](https://developers.openai.com/api/docs/guides/image-generation)。其他服务商仅在兼容这两个接口、Bearer 认证及 `b64_json` PNG 返回格式时可用；不能承诺任意生图 API 通用。

准备：你自己的服务商账号、已开通的图片模型、API Key。服务商可能需要余额或组织验证；按该账号计费。默认地址是 OpenAI 官方 `/v1`，默认模型 `gpt-image-2`；可用 `--model` 指定你账号实际支持的模型。自定义服务必须显式传 `--base-url https://你的服务地址/v1`，提示词和参考图会上传到这个服务。

下面命令中的 `<安装目录>` 和 `<产品目录>` 是路径占位符，请让 Agent 替换成你的真实绝对路径。路径有空格时保留引号。Python 环境需先安装本 Skill 的 requirements.txt。

### 1. 检查接入入口（不联网）

```bash
python3 "<安装目录>/scripts/image_backend.py" doctor
```

`doctor` 只显示是否存在环境变量、当前终端能否隐藏输入，不显示 Key，也不证明账号或模型已经可用。

### 2. 先准备一张海报任务

```bash
python3 "<安装目录>/scripts/generate_image_asset.py" \
  --title "产品需求实操课" --point "把想法整理成可执行需求" \
  --scene marketing_poster --template cyber-bold-poster-v1 \
  --output-dir "<产品目录>/制作记录/赛博海报-v1"
```

`--template` 选择黑底赛博大字模板，`--output-dir` 放本次提示词和任务记录，必须使用新目录。文案换成你已确认的真实产品资料。

### 3. 预览请求，再实际生成

```bash
python3 "<安装目录>/scripts/image_backend.py" render \
  --manifest "<产品目录>/制作记录/赛博海报-v1/image-asset-manifest.json" \
  --output "<产品目录>/images/赛博海报-v1.png"
```

默认只预览目标服务、模型、尺寸、参考图数量和输出位置，不联网、不收费。实际生成时，在同一命令末尾加：

```text
--execute --allow-paid
```

请在**你自己的交互式终端**运行。程序会提示输入 API Key，输入不回显；按回车后请求一张图片。Key 只留在该进程内存中，不写配置文件、不进入命令历史、不存到仓库。每次新运行需要重新输入。

如果希望 Agent 在当前终端会话连续生成多张图，可以由你本人先执行以下命令（macOS 的 zsh）：

```zsh
read -rs 'IMAGE_FACTORY_API_KEY?API Key（隐藏输入）: '
export IMAGE_FACTORY_API_KEY
```

Bash 使用 `read -rs -p 'API Key（隐藏输入）: ' IMAGE_FACTORY_API_KEY` 后再 `export IMAGE_FACTORY_API_KEY`。只在这个终端及其子进程中生效：从同一终端启动 Agent，或让它在同一进程环境执行命令。已打开的桌面 Agent 不会自动继承另一个终端的新变量。用完执行 `unset IMAGE_FACTORY_API_KEY`。不要让 Agent 查询、打印或把变量写进文件。

### 4. 验收，再交给小店清单

出图成功会得到 PNG 和 `.receipt.json`，初始状态是 `awaiting_visual_review`。让 Agent 展示图片，检查文案、错字、商品事实及布局，合格后执行：

```bash
python3 "<安装目录>/scripts/accept_image.py" \
  --manifest "<产品目录>/制作记录/赛博海报-v1/image-asset-manifest.json" \
  --image "<产品目录>/images/赛博海报-v1.png" \
  --destination "<产品目录>/images/赛博海报-v1.png" --visual-approved
```

回执变为 `ready` 后，store-listing-kit 将真实图片路径加入 HTML 交接清单。内置生图和 API 生图共用这份回执，不需要另外整理一套文件。

## 失败时怎么办

- 没有 Key，且运行环境不能交互输入：到本地终端运行，或让用户在启动 Agent 前注入环境变量。
- HTTP 401/403：检查服务商后台的 Key 权限、余额或模型权限，不把 Key 发给 Agent。
- HTTP 400：核对该服务是否支持模型、尺寸、PNG 格式和参考图编辑协议。
- 超时、无效响应：程序不自动重试，并保留 `.render-lock` 防止重复计费。先查看服务商请求记录与本地输出；明确本次结果后，手动移除该任务锁再决定是否重新请求。
- 图片尺寸/格式不合格：不会生成 ready 回执；收到的数据暂存为 `.unverified.bin`，由 Agent 检查后处理，不能当作已完成图片。
- 已有输出：拒绝覆盖。先检查已有图，确需重做则用新的版本名。

API 路径已通过模拟请求、鉴权边界、参考图上传和图片回执测试；未使用作者私人 Key 做付费服务实测。首次接入请先生成一张确认效果，再运行整套。
